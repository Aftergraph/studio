# V8.1 Distributed Aftergraph — Deferral and Naming Boundary

Status: ROADMAP MILESTONE DELIVERED (single-process scope, 2026-09-07)

`docs/ROADMAP.md` defines V8.1 as Distributed Aftergraph:

- multiple nodes, devices and runtimes;
- edge/local/cloud federation;
- offline-first operation;
- eventual convergence without authority leakage.

That milestone is not implemented in the current repository. The current V8.1-labelled work is an audit/remediation stream and is now explicitly named `V8.1-A` in the release verifier:

- V8.1-A Backend Contract Boundary
- V8.1-A Destructive Action Guard

The V8.1-A stream closes frontend/runtime correctness findings from the V8.1 audit. It does not claim distributed convergence, offline replication, multi-node identity, conflict resolution or edge authority.

Promotion rule for the actual V8.1 milestone:

1. Define node identity and source-of-truth ownership.
2. Define offline event envelope, replay/idempotency and conflict policy.
3. Define convergence tests across at least local, edge and cloud projections.
4. Prove authority does not leak through stale, replayed or conflicting replicas.
5. Add a distinct V8.1 Distributed Aftergraph exit gate and changelog entry.

## Delivered 2026-09-07 (single-process scope)

1. Node identity: `src/distributed/node-identity.mjs`.
2. Offline event envelope + replay/idempotency: `src/distributed/offline-event-log.mjs` (idempotent merge, vector clocks in `src/distributed/vector-clock.mjs`).
3. Conflict policy: first-writer-wins per event id, proven by `tests/v81-distributed-convergence.test.mjs` (`src/distributed/convergence.mjs` total order).
4. Server sync: `POST/GET /api/v1/sync/events` over `src/distributed/server-log.mjs` with actor, nodeId and idempotency-key validation.
5. Offline-first client: `src/distributed/offline-client.mjs` (local-first truth, fail-closed sync, pending count) with `submitSync`/`readSync` in `src/api-client.mjs`.
6. Exit gate: `V8.1 Distributed Aftergraph Exit Gate` over `tests/v81-distributed-offline-client.test.mjs`, including an end-to-end offline → server → convergence proof with an active tamper attempt.

Known ceiling (ponytail): server and client logs are in-memory and single-process; durable multi-process/edge replication with persistent vector-clock cursors is the upgrade path when real edge nodes exist.
